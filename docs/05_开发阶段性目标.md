# 个人分布式云盘系统：按顺序运行的开发阶段性目标

本路线是唯一推荐顺序。阶段必须串行通过退出门禁；可在阶段内部并行开发互不依赖的工作，但不得跳过前置契约和验证直接做 GUI 或公网功能。

## 总体顺序

```mermaid
flowchart LR
  M0[M0 基线与原型] --> M1[M1 工程骨架]
  M1 --> M2[M2 单机对象闭环]
  M2 --> M2D[M2-D Docker 云原生基线]
  M2D --> M3[M3 控制面与同步]
  M3 --> M4[M4 LAN 传输]
  M4 --> M5[M5 恢复与换源]
  M5 --> M6[M6 公网与 Relay]
  M6 --> M7[M7 副本与冗余]
  M7 --> M8[M8 回收站与 GC]
  M8 --> M9[M9 桌面产品闭环]
  M9 --> M10[M10 Android 与发布]
```

## M0：需求/架构基线与风险原型

目标：在大规模编码前证明最高风险假设。

交付物：

- 需求、架构、代码规范、详细设计批准；开放项有 owner 和关闭阶段。
- 锁定 Go、PostgreSQL、SQLite、go-libp2p、Fyne、Android target API 和代码生成工具版本。
- 四个可丢弃原型：两 peer libp2p 直连/Relay；PostgreSQL 并发任务领取；SQLite `.part` 崩溃恢复；Android SAF + 后台长传输 + 通知。
- 记录原型环境、命令、网络拓扑、结果和失败限制。

退出门禁：

- libp2p 在真实 socket 上完成带身份校验的流传输，不只是内存 transport。
- Android 真机能在当前系统限制内展示可取消传输；若 Fyne 桥接失败，正式选择原生外壳。
- 明确哪些能力未经真实 NAT/真机验证，不作成功声明。

## M1：工程骨架与可执行契约

目标：建立所有后续阶段共用的编译、测试和契约基础。

交付物：

- Go module、目录结构、Makefile/CI、配置加载、结构化日志、Clock/ID 抽象。
- OpenAPI 初版、Proto 初版、PostgreSQL/SQLite 空库迁移。
- `control-server`、`control-worker`、`agent`、`cli` 可启动，提供 live/ready/version。
- 生成文件一致性、迁移 smoke test、依赖漏洞扫描。

退出门禁：`make check` 在干净环境通过；空数据库可迁移；所有二进制可构建和优雅退出。

## M2：单机对象存储闭环

目标：不依赖网络完成可靠导入、校验、查询和本地删除。

交付物：

- `storage/hasher/catalog`：受管目录、流式 SHA-256、4 MiB chunk manifest、Hash 路径。
- SQLite local objects、导入状态机、`.part`、原子 rename、启动扫描修复。
- CLI：`file import`、`file stat`、`object verify`、`status`。
- 路径规范化、磁盘空间、重复导入和命名冲突测试。

退出门禁：1 GiB 导入不整文件入内存；进程在写入/校验/rename 各点退出后可恢复，未校验对象绝不为 READY。

## M2-D：服务器 Docker 云原生基线

目标：在继续扩展控制面业务前，把 server/worker 的构建、配置、迁移、健康和退出固化为可复现容器契约。M1/M2 当前并未通过各自退出门禁（见 [`todo/README.md`](./todo/README.md)）；本阶段是新增强制门禁，不把“存在部分实现”当作“阶段完成”。

交付物：

- `deploy/docker/Dockerfile` 多阶段构建 `control-server`、`control-worker` 和 `db-migrate` 独立目标；仓库根 `.dockerignore`。
- `deploy/compose/compose.yaml`、非机密 `.env.example`、secret 初始化说明、PostgreSQL 持久卷和内部网络。
- 配置 `*_FILE`、schema readiness、无 shell 健康检查入口、`signal.NotifyContext` 优雅退出和 worker 明确等待组。
- `make image/compose-config/container-test/image-scan` 与 CI 镜像构建、SBOM、漏洞/秘密扫描。
- 运维最小闭环：首次启动、迁移、停止、升级/回滚、数据库备份恢复和常见故障排查。

退出门禁：全新 Docker 环境完成 `postgres healthy -> migrate success -> server/worker ready`；应用容器以非 root/只读根文件系统运行；SIGTERM、数据库中断、迁移失败和容器重建测试通过；只有 PostgreSQL 卷保留服务端权威状态。详细差距和配置草案见 [`todo/README.md`](./todo/README.md)。

## M3：账号、设备、目录与可靠同步

目标：Control Server 成为元数据权威源，多 Agent 断线后可收敛。

交付物：

- 首账号 bootstrap、登录/刷新/注销、Argon2id、设备密钥注册与会话撤销。
- folders、file objects/entries、replicas、idempotency、account events 迁移和应用服务。
- REST/OpenAPI 客户端、WebSocket 提示、cursor delta sync 和 snapshot 回退。
- Agent 本地缓存、outgoing ops、服务端断线重试。

退出门禁：两个 Agent 的目录/设备状态一致；人为丢弃/重复/乱序 WebSocket 后仍通过游标收敛；写请求重放不产生重复记录。

## M4：局域网 P2P 端到端传输

目标：完成 A 导入、B 仅见元数据、B 在 LAN 下载并登记 READY。

交付物：

- libp2p host、mDNS/local discovery、同账号 peer 过滤。
- 版本化 transfer protocol、票据、chunk request/data/ack。
- TransferTask 创建/领取/租约/结果；候选源选择。
- CLI：`file pull`、`transfer list/show/cancel`。

退出门禁：两个独立进程和独立存储目录完成 1 GiB LAN 传输；源端拒绝错误账号、目标、对象、过期票据和伪造 PeerID。

## M5：断点续传、换源与资源控制

目标：把“能传”提升为“故障后可靠完成”。

交付物：

- chunk 位图持久化、应用重启恢复、连接重拨和候选源切换。
- 并发/带宽/缓冲上限、空间预留、暂停/继续/重试、稳定错误分类。
- 三 Agent 测试：A/C 有副本，B 从 A 开始并切到 C。
- 性能基线工具和固定参数报告格式。

退出门禁：10 GiB 传输重启后只请求缺失块；源切换后完整 Hash 一致；内存峰值由 chunk×并发界定，不随文件线性增长。

## M6：公网直连与 Relay

目标：跨网络优先直连，失败后受控中继。

交付物：

- AutoNAT、hole punching、Relay reservation、Bootstrap 配置。
- LAN/DIRECT_WAN/RELAY/NONE 路径观测与切换。
- Relay 连接/并发/时长/字节限额和指标。
- 可复现 NAT 网络实验与至少一次真实异网验证。

退出门禁：直连和强制 Relay 两条路径都完成完整传输；控制服务器磁盘审计无文件正文；Relay 重启后任务可恢复。

## M7：主动推送、副本管理与自动冗余

目标：在统一 TransferTask 上完成副本产品语义。

交付物：

- `file push`、`replica create/remove/list`；离线目标保持持久队列。
- 副本验证、MISSING/CORRUPT 上报与降级提示。
- 冗余策略、硬过滤、确定性评分、任务去重和不足修复。
- Android 移动网络/充电策略先作为能力字段和调度约束接入。

退出门禁：desired=2 自动补齐且并发协调器不重复建任务；删除副本前能识别独占/降级风险；目标离线上线后继续。

## M8：回收站、Tombstone 与物理 GC

目标：完成可恢复删除并证明长期离线副本不会复活。

交付物：

- 7 天回收站、恢复冲突、立即永久删除、定时 purge。
- tombstone generation/ack、注销设备处理、对象引用判定、本地 GC。
- 可注入时钟和离线 30 天模拟测试。

退出门禁：共享同一对象的两个 FileEntry 删除一个不影响另一个；离线设备携带旧副本上线只收到删除指令；恢复与 purge 竞争结果确定。

LAN V1 前置切片：先完成单 Ubuntu Agent 内的发现、重命名、7 天回收站、恢复和引用安全的永久删除，并通过 Android 与真实 HTTP/SQLite E2E。跨设备 tombstone/ACK 仍属于完整 M8，不能用本地回收站测试替代。

## M9：桌面 GUI 与日常运维闭环

目标：Windows/Linux 用户无需 CLI 即可完成 V1 主要操作。

交付物：

- 云盘、传输、设备、回收站、设置和属性抽屉。
- tray/开机启动/systemd user service、升级和日志导出。
- 加载、空、离线、冲突、磁盘不足、降级和危险操作确认状态。
- PostgreSQL 备份/恢复复验、TLS、监控和生产运维手册；Compose 基线已在 M2-D 建立，此阶段补齐面向日常发布的演练。

退出门禁：Windows/Linux 安装包冒烟；GUI 与 CLI 调用同一 Agent 服务；备份恢复演练通过；AC-02..12 中非 Android 项通过。

## M10：Android、跨平台验收与 V1 发布

目标：交付 Android 可用产品并完成全量 V1 验收。

交付物：

- 登录、目录、导入、下载/推送、副本、传输通知和策略设置。
- SAF、User-Initiated Data Transfer/WorkManager/前台服务适配，按 M0 决策实现。
- Android 电池、网络切换、进程回收、权限撤销和存储不足测试。
- Windows/Linux/Android 三端版本兼容矩阵、升级/回滚、发布说明。

退出门禁：AC-01..16 全部有实际证据；Android 真机后台限制已验证；未验证的特定 NAT/厂商行为列为已知限制，不以模拟器结果替代。

## 阶段执行规则

每阶段按以下固定循环执行：

1. 入口审查：上阶段门禁通过，契约和迁移无未决破坏性变更。
2. 纵向切片：先完成最小真实端到端路径，再补错误和边界，不按“先写完所有层”横向堆积。
3. 自动验证：单元、集成、契约、race、安全检查按风险运行。
4. 真实验证：涉及文件系统、网络、数据库、平台时使用真实依赖；mock 仅覆盖不可控边缘。
5. 文档同步：OpenAPI、Proto、迁移、状态机、运维文档与代码一致。
6. 退出评审：保存命令、参数、结果和未验证项；门禁失败不得启动下一阶段。
7. 服务器阶段额外执行镜像/Compose/容器 E2E/扫描门禁；宿主机二进制测试不能替代容器验证。

## V1 发布完成定义

- 需求 AC-01..16 均有可复现测试或明确的真机/网络验证记录。
- 控制服务和 Relay 无文件正文持久化；安全扫描和秘密扫描无未处理高风险项。
- 10 GiB 中断、切源、重启、磁盘不足和校验失败均有证据。
- 数据库从空库迁移、备份恢复和二进制回滚流程实际执行。
- 所有服务器职责以可追溯 OCI 镜像发布；Compose 从空环境部署、不可变镜像回滚、非 root/只读运行和 secret 轮换均有实际证据。
- 三平台安装、升级、卸载和本地数据保留语义明确。
- 所有已知限制、运维前提和未验证外部环境如实列出。
