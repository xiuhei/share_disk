# 局域网部署与使用

本文面向 Share Disk LAN V1 的使用者。当前范围是一个账号、一台 Ubuntu 存储 Agent 与一个 Android 10+ 客户端，设备必须位于同一可信局域网。文件正文保存在 Ubuntu Agent；Docker Compose 只运行 PostgreSQL、迁移、Control Server 和 Control Worker。

## 前置条件

- Ubuntu 22.04/24.04 x86-64，已安装 Docker Engine、Docker Compose 插件和 OpenSSL。
- Android 10+；首次验证可侧载调试 APK。设备与 Ubuntu 位于同一受信网络。
- 部署目录不可被其他用户写入。不要把调试 HTTP 端口或 `conf/server.json` 暴露到公网。

## 启动控制面

在仓库根目录执行：

```bash
./deploy/compose/server.py init
$EDITOR conf/server.json
./deploy/compose/server.py up -d --build --wait
```

`init` 只会创建一次权限为 `0600` 的 `conf/server.json`。该文件含数据库密码、初始化令牌和签名私钥，不能提交或复制到客户端。用下列命令确认服务已就绪：

```bash
curl -fsS http://127.0.0.1:8080/readyz
./deploy/compose/server.py ps
```

停止服务使用 `./deploy/compose/server.py down`。生产使用时应把 Control Server 放在受信 TLS 反向代理之后；默认 Compose 的端口只适用于本机/局域网验收。

## 安装 Ubuntu Agent

构建软件包：

```bash
make deb DEB_VERSION=0.3.0
sudo dpkg -i dist/share-disk_0.3.0_amd64.deb
sudoedit /etc/share-disk/agent.env
sudo systemctl restart share-disk-agent
sudo systemctl status share-disk-agent
```

配置中至少需要 SQLite 路径、对象存储目录、Control Server 地址、Agent 对外可达地址和 Control Server 的 Ed25519 公钥。Agent 可以启用 `SHARE_DISK_LAN_DISCOVERY_ENABLED=true` 发布 DNS-SD 候选地址；发现不是信任依据，Android 仍必须完成账号和令牌认证。多播不可用时在 Android 中手工填写 Agent URL。

## Android 使用

从 `android/` 构建调试包：

```bash
export ANDROID_HOME=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk-17
cd android && ./gradlew --no-daemon assembleDebug lintDebug
```

安装 `app/build/outputs/apk/debug/app-debug.apk` 后：

1. 选择发现到的 Agent 或输入其局域网 URL。
2. 首次部署时使用初始化令牌创建账号；之后使用账号登录。
3. 在“文件”页通过系统文件选择器上传，等待完成状态和 SHA-256 校验。
4. 从文件列表选择下载位置；下载走 HTTP Range，可在应用重启后由 WorkManager 继续。
5. 删除的文件先进入回收站，可恢复；永久删除后内容不可恢复。

调试构建可在可信隔离 LAN 使用 HTTP。任何正式网络接入都必须使用受信 TLS；不要在 APK、脚本或 Git 中保存令牌、私钥、Keystore 或密码。

## 接口与验收边界

控制面契约见 [`../api/openapi/openapi.yaml`](../api/openapi/openapi.yaml)，本地 IPC/P2P 契约见 [`../proto/sharedisk/v1/`](../proto/sharedisk/v1/)。本仓库的可重复自动验证命令为：

```bash
make check
make test-int
make lan-e2e
make lan-e2e-docker
```

这些命令覆盖真实 PostgreSQL、SQLite、容器、TCP 上传/Range 下载、哈希、重命名、回收站、恢复/永久删除和重启持久性。它们不替代 Android 真机验收：仍需在目标 Wi-Fi、SAF 提供方、进程被杀、设备重启与大文件/断网恢复情景下完成验证。
