# 个人分布式云盘系统：代码规范

本规范适用于服务端、Worker、Agent、CLI、桌面端共享 Go 代码及协议/数据库资产。服务器代码还必须服从本文的 OCI 镜像与 Docker 运行契约。Android 原生桥接另遵循 Kotlin 官方风格，但必须服从本文的接口、安全和测试边界。

## 1. 仓库与包结构

```text
cmd/
  control-server/  control-worker/  agent/  desktop/  cli/
internal/
  identity/ catalog/ replica/ transfer/ trash/ sync/
  controlapi/ controlclient/ localapi/
  storage/ p2p/ scheduler/ platform/
api/openapi/         # 控制面契约
proto/sharedisk/v1/  # P2P 与本地 IPC 协议
migrations/postgres/
migrations/sqlite/
deploy/docker/          # 多阶段 Dockerfile 与容器入口资产
deploy/compose/         # Compose、反向代理、非机密环境模板
test/e2e/ test/fixtures/
docs/
```

- 默认单个 Go module；只有出现独立发布和明确依赖边界时才拆 module。
- `internal` 包按业务能力命名，禁止 `utils`、`common`、`misc`、`helpers` 垃圾桶包。
- 领域包不得依赖 HTTP、GUI、数据库驱动或 libp2p；适配器依赖领域接口。
- `pkg` 仅放确实要给仓库外使用的稳定公共 API；V1 默认不创建。
- 生成文件写明生成器和命令，禁止手改；生成结果与输入契约一同提交。

## 2. Go 基础规范

- 所有代码必须通过 `gofmt`；导入使用 `goimports`。
- 包名小写单词；导出名注释以名称开头；缩写保持一致，如 `ID`、`URL`、`HTTP`。
- 接口由使用方定义，保持小而具体；不要为“以后可能替换”预建接口。
- 构造函数验证必需依赖；禁止隐藏的包级可变单例。
- 零值有明确语义；无法区分“未提供”和零值时使用指针或显式 Optional 类型。
- 时间统一存 UTC，边界使用 `time.Time`；持续时间使用 `time.Duration`，不得用裸整数表达秒。
- 大小和偏移使用 `int64`；Hash 使用固定长度值类型，不在领域层到处传裸字符串。
- 枚举采用自定义字符串类型并在解析边界拒绝未知值；数据库约束同步校验。
- 函数优先少于 50 行且单一职责；不是机械上限，复杂状态转换应拆成可命名规则。

参考 [Effective Go](https://go.dev/doc/effective_go) 和 [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments)，但以当前 Go 工具和本项目约束为准。

## 3. 错误处理

- 业务错误使用稳定代码：`NAME_CONFLICT`、`NO_READY_REPLICA`、`TICKET_EXPIRED`、`INSUFFICIENT_SPACE` 等。
- 仅在需要调用方分支处理时定义哨兵/类型错误；其余用 `%w` 保留原因链。
- 每层最多补充一次有价值上下文，不重复打印同一错误；日志只在请求/任务边界记录一次。
- 不用 `panic` 表示可预期输入、网络、磁盘或数据库错误；`panic` 仅用于不可恢复的编程不变量。
- HTTP 错误响应统一为 `code/message/request_id/details`；生产环境不返回 SQL、路径、堆栈或内部类型。
- 重试必须由明确的错误分类驱动：`permanent`、`retryable`、`waiting_external`；禁止对所有错误无条件重试。

## 4. Context、并发与生命周期

- 所有 I/O 边界首参数为 `context.Context`；不得把 Context 存入结构体。
- goroutine 必须有 owner、取消路径和退出等待；禁止裸 `go func()` 后无人收尾。
- 后台组件统一 `Run(ctx) error`，由顶层 `errgroup` 管理；关闭顺序为停止接入、取消任务、等待、关闭存储。
- channel 用于所有权移交或事件流，不用来替代互斥锁保护普通状态。
- 不持锁执行网络、磁盘或数据库 I/O；需要多把锁时定义并遵守固定顺序。
- 传输并发由有界 semaphore 控制；队列、缓冲区、消息大小和重试次数都必须有上限。
- 所有并发状态机测试至少运行 `go test -race`；使用可注入 Clock，测试中禁止依赖 `time.Sleep` 猜时序。

## 5. 文件与存储

- 文件写入只允许 `incoming/<task>.part -> 校验 -> fsync -> 原子 rename -> SQLite commit` 流程。
- 对象路径只能由验证后的 Hash 生成；用户文件名不得参与对象路径拼接。
- 不一次性读取大文件；所有 Hash、复制、上传和下载使用流式 I/O 和有界 buffer。
- 处理短写、EOF、磁盘满、跨文件系统 rename、文件占用和取消。
- SQLite WAL 仅用于本机磁盘，不放网络文件系统；备份必须把 WAL 状态纳入一致性处理。
- 平台差异只进入 `internal/platform/<os>` 适配器，领域层不得散布 `runtime.GOOS` 条件。

## 6. SQL 与迁移

- 所有表有主键、外键、必要唯一约束、`created_at/updated_at`；软删除状态必须有索引策略。
- 金额之外的计数、大小、序号使用匹配范围的整数；禁止把 JSONB 当作逃避建模的默认方案。
- SQL 参数化；禁止字符串拼接用户输入、列名和排序字段，动态部分必须白名单。
- 事务尽量短；进入事务前完成 Hash、网络和大文件 I/O。
- 所有并发业务规则由数据库约束或锁保护，不能只靠 Go 中“先查后写”。
- 多行锁按稳定主键顺序获取；捕获死锁/序列化失败时重试整个事务。
- 迁移只向前、带版本、可在空库执行；破坏性变更采用 expand/migrate/contract。
- 每个查询明确超时；列表必须分页，禁止无界 `SELECT *`。

## 7. HTTP、WebSocket 与协议

- OpenAPI 文件是 HTTP 契约源；实现、客户端和契约测试由同一版本生成或验证。
- URL 用复数资源；JSON 字段 `snake_case`；时间 RFC 3339 UTC；二进制 Hash 用小写十六进制。
- POST 写操作要求 `Idempotency-Key`；分页使用稳定 cursor，不使用大 offset。
- `PATCH/DELETE` 携带对象 `version` 或 `If-Match`，冲突返回 `409`。
- WebSocket 消息只含通知序号和轻量状态，不承载不可恢复的唯一任务指令。
- Protocol Buffers 字段号发布后永久保留；删除字段必须 `reserved`；不改变既有字段含义。
- P2P 每个 frame 有长度上限；握手先验证协议版本、票据、PeerID 和对象，再允许读数据。
- 公开错误代码和状态转换必须有契约测试。

## 8. 安全编码

- 凭据来自环境变量/安全存储，仓库只提交 `.env.example`；日志和错误不得打印秘密。
- 密码比较、Token Hash 比较使用恒定时间函数；随机值使用 `crypto/rand`。
- 自定义加密算法、签名格式和密钥派生禁止进入生产；使用标准库或成熟库。
- 文件名、路径、MIME、Peer 地址、协议长度和 JSON 体积全部视为不可信输入。
- transfer ticket 最短权限、短 TTL、绑定源/目标/对象；拒绝“知道 Hash 就能下载”。
- HTTP 配置读/写/空闲/头超时与请求体上限；Relay/P2P 配置流量、连接和并发限额。
- 依赖用 Go module 锁定，提交 `go.mod/go.sum`；CI 运行 `govulncheck`。

## 9. 日志与指标

- 使用 `log/slog` 作为统一 API；库代码接收 logger，不自行配置全局输出。
- 日志是结构化事件，不拼接长文本；错误字段保留 `error`，业务字段名稳定。
- 不记录密码、Token、票据、私钥、完整本地路径；文件名默认不进入服务端日志。
- 高频块传输不逐块打 info；以任务周期聚合指标，失败块可采样 debug。
- 指标标签禁止账号、文件名、完整 Hash、task_id 等高基数字段。

## 10. 测试规范

- 领域单元测试：表驱动，覆盖状态合法/非法转换、边界和幂等。
- 存储集成测试：真实 PostgreSQL/SQLite，验证唯一约束、锁、迁移和崩溃恢复。
- 协议契约测试：OpenAPI 请求/响应、Proto 兼容、错误代码和大小限制。
- P2P 集成测试：进程内 transport 可用于快速反馈，但 LAN/Relay 最终测试必须使用真实 socket。
- E2E：多个独立 Agent 目录和进程；不可共享 SQLite 或对象目录制造假成功。
- 故障注入：断网、进程退出、源切换、磁盘满、重复消息、乱序通知、Token 过期。
- 性能测试固定文件大小、chunk、并发、网络条件和轮数；记录中位数/P95、内存峰值、错误和完整性。
- 测试不得仅验证 mock 被调用；必须断言最终业务状态和持久数据。

## 11. 容器与云原生编码规范

- `control-server`、`control-worker`、`db-migrate` 和后续 `relay-bootstrap` 分别作为单职责镜像目标；不得用 supervisor 在一个容器内管理多个长期进程。
- Dockerfile 必须多阶段构建并使用仓库根目录作为受控 build context；`.dockerignore` 排除 `.git`、`bin/`、`data/`、测试输出、编辑器文件、凭据和本地配置。
- 生产镜像只包含运行必需文件，固定非 root UID/GID，默认 `read_only`、`cap_drop: [ALL]`、`security_opt: [no-new-privileges:true]`；禁止 privileged、宿主网络和 Docker socket。
- 基础镜像使用明确版本并由自动化定期更新；生产发布记录解析后的镜像 digest。镜像标签至少包含版本和 Git commit，不使用可漂移的 `latest` 作为生产依据。
- 服务不得依赖当前工作目录或容器 hostname；只写 stdout/stderr。确需临时文件时写有大小限制的 `/tmp` tmpfs，权威状态不得写容器可写层。
- 普通配置用环境变量；机密实现对应 `*_FILE` 读取，直接环境变量仅用于本地兼容且不得输出。仓库只提交 `.env.example` 的非秘密键和值说明。
- `control-server` 在容器内默认监听 `0.0.0.0`，但数据库、metrics 和管理端口由 Compose 网络限制，不因此直接暴露公网。
- 进程必须直接作为 PID 1 或由 Compose `init` 转发信号；使用 `signal.NotifyContext`/明确等待组处理 `SIGTERM`。不得在后台 goroutine 中 `os.Exit`，不得用固定 `time.Sleep` 假装完成清理。
- liveness 不访问外部依赖；readiness 使用有界 context 检查数据库、迁移版本和关键循环。镜像内必须提供无需 shell/curl 的健康检查子命令或等价静态探针。
- 迁移由一次性 `db-migrate` 容器执行并持 PostgreSQL advisory lock；server/worker 只检查 schema 兼容性，禁止启动时自动竞争迁移。
- Compose 必须声明健康依赖、停止宽限期、重启策略、资源边界、内部网络和唯一持久卷；配置中不得出现真实密码、Token、证书或私钥。
- CI 必须构建每个镜像目标，校验 Compose，运行容器 E2E，生成 SBOM 并扫描镜像；只有语法校验不得作为云原生交付完成证据。

## 12. 工具与持续集成门禁

建议统一提供以下命令，具体版本在 Stage 0 锁定：

```text
make fmt       # gofmt/goimports 检查
make lint      # go vet + staticcheck
make test      # 单元测试
make test-race # 核心包 race
make test-int  # PostgreSQL/SQLite/进程集成
make contract  # OpenAPI/Proto/迁移一致性
make vuln      # govulncheck
make build     # 全部当前平台目标
make image     # 构建全部服务器 OCI 镜像
make compose-config # 解析并校验 Compose 与必需变量
make container-test # PostgreSQL + 迁移 + server/worker 容器 E2E
make image-scan # SBOM、漏洞与秘密扫描
make check     # CI 必过集合
```

CI 不得自动修改仓库后继续通过；格式、生成文件或迁移有差异应直接失败。

在 Docker 改造门禁完成后，`make check` 必须包含 `compose-config`，发布 CI 还必须包含 `image`、`container-test` 和 `image-scan`。本地缺少 Docker 时可以运行非容器快速检查，但必须明确标注容器门禁未验证。

## 13. 代码评审与完成定义

每个变更必须满足：

- 关联需求 ID/缺陷与可观察行为；没有无关重构。
- 数据所有权、失败路径、并发和安全边界已说明。
- 新依赖说明必要性、许可证、维护状态和替代方案。
- 代码、测试、契约、迁移和受影响文档同步。
- 服务端变更同步检查 Dockerfile、Compose、探针、迁移顺序、资源/权限边界和镜像兼容性。
- 实际执行相关测试并记录命令；未执行的真机、外网或性能验证明确标注。
- 不提交秘密、临时产物、个人路径、生成缓存或虚假的性能结论。
