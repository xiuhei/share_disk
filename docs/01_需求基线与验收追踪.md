# 个人分布式云盘系统：需求基线与验收追踪

版本：v1.3-lan
来源：`个人分布式云盘系统_需求与总体设计_v0.1.docx`
用途：把原始 PRD/HLD 转成可直接驱动架构、接口、测试和阶段验收的需求基线。

## 1. 问题与目标

用户拥有 Ubuntu 和 Android 设备，但不希望把真实文件永久托管到中心云存储。首个可交付版本先提供同一可信局域网内的文件上传、浏览和下载；文件正文和 LAN 文件目录保存在 Ubuntu Agent，Docker 控制面在这个阶段只负责账号、首设备和会话凭据。

成功结果：用户只安装 Docker/Compose、Ubuntu Agent 和可侧载 APK，即可从 Android 登录、选择文件上传到 Ubuntu、浏览已上传文件、下载到 Android，并由两端核对文件大小和 SHA-256。网络中断不会产生可见的半文件，重试可继续或安全重建传输。

## 2. 参与者

- 账号所有者：管理文件、目录、设备、副本、传输、回收站和策略。
- Device Agent：管理本地对象、执行任务、验证副本、参与 P2P 传输。
- Control Server：认证、元数据权威源、任务协调、授权签发和同步游标。
- Relay/Bootstrap：P2P 引导与临时加密字节流中继，不永久保存文件。
- 平台运行时：Windows/Linux 服务管理、Android 存储与后台任务机制。
- 服务端运行环境：Docker Engine/Compose 负责服务器进程隔离、配置注入、健康检查、持久卷和升级回滚。

## 3. 范围边界

### 3.1 LAN V1 范围

- 单账号、一个 Ubuntu 22.04/24.04 存储节点、一个 Android 10+ 主客户端，均位于同一可信局域网。
- Docker Compose 部署 PostgreSQL、迁移任务、Control Server 和 Control Worker；Ubuntu Agent 作为宿主机进程管理文件正文。
- Android APK 支持 DNS-SD 自动发现或手工配置 Agent 地址、首次初始化或登录、系统文件选择器上传、文件列表、重命名、回收站、系统文件创建器下载和可见传输状态。
- Ubuntu CLI 支持导入、列表、状态、校验和下载对象；所有本地写入继续经过 Agent。
- Android 与 Ubuntu Agent 之间进行认证的流式传输；上传可恢复，下载支持 HTTP Range，完成后核对完整 SHA-256 并原子发布。
- 控制面保存账号、首设备和会话凭据；LAN 文件目录由 Ubuntu Agent SQLite 保存，控制面不持久化文件正文或完整分块。全局文件元数据同步属后续阶段。
- 提供真实 Docker、Agent、HTTP 和 Android 构建门禁，以及可由第二台局域网设备重复执行的 E2E 脚本和操作说明。

### 3.2 明确排除

- 多人空间、团队协作、复杂 ACL、跨账号去重。
- 在线 Office、视频转码、全文内容索引。
- Windows、NAS 专用 UI、桌面 GUI、虚拟盘符/FUSE、文件版本、多源并行下载和外部分享。
- 公网访问、NAT 穿透、Relay、自动冗余、跨来源切换和多人共享；这些能力在 LAN V1 通过后再进入后续里程碑。
- 服务端文件对象存储、Relay 持久化、隐藏式 Android 无限后台常驻、应用商店发布和自动更新。
- LAN V1 不承诺在不可信 Wi-Fi 上以明文 HTTP 安全运行；正式部署必须使用受信 TLS 入口，明文只允许显式开启的隔离测试网。
- V1 不强制交付生产 Kubernetes 集群、Service Mesh 或拆分微服务；容器运行契约必须保持可迁移到编排平台。

## 4. 必须始终成立的业务不变量

1. 服务器和 Relay 不得把文件正文或完整分块作为长期数据保存。
2. 只有完整 SHA-256 校验成功的本地对象才能形成 `READY` 副本。
3. 文件正文身份为账号内 `(sha256, size)`；逻辑路径、名称和来源设备不是对象身份。
4. 一个对象可被多个逻辑文件引用；删除单个逻辑文件不能破坏其他引用。
5. 逻辑删除、回收站、删除指令和本地物理回收是不同阶段。
6. `READY` 只表示最近一次验证有效；服务端历史记录不能替代设备真实校验。
7. 所有跨设备读取必须同时验证账号、对象、源、目标、期限和设备身份。
8. WebSocket 只提供低延迟通知；持久任务和元数据必须能在重连后补拉。
9. 所有可重试写请求必须带幂等键；相同键与不同请求体组合必须被拒绝。
10. 元数据写操作在 V1 需要连接 Control Server；服务器不可用时只允许本地文件访问和任务暂存，不接受可能冲突的离线目录写入。
11. `control-server` 和 `control-worker` 不得依赖容器本地可变状态；服务器唯一持久状态进入 PostgreSQL，机密不得写入镜像、Compose 文件或日志。
12. 数据库迁移必须由可审计的一次性任务显式执行；应用容器启动不得并发或隐式执行破坏性迁移。

## 5. 原始需求归并

原文需求 ID 原样保留，作为实现和测试的稳定引用：

- `FR-AUTH-001..005`：密码登录、Token、撤销会话、新设备确认。
- `FR-DEV-001..007`：设备身份、注册、心跳、发现、状态、容量、注销。
- `FR-FILE-001..007`：目录与文件、导入、内容寻址、账号内去重、查询和监控目录。
- `FR-XFER-001..008`：源选择、分块、校验、恢复、原子落盘、限速和任务控制。
- `FR-PUSH-001..003`：向在线或离线目标设备创建自动接收任务。
- `FR-REP-001..004`：副本属性、手动副本和自动冗余策略。
- `FR-TRASH-001..005`：7 天回收站、恢复、永久删除和防复活 tombstone。
- `NFR-001..009`：可靠性、完整性、流式资源、服务成本、可观测性、恢复、移植和隐私。

## 6. 为实现闭环补充的需求

| ID | 优先级 | 补充需求 | 验收方式 |
|---|---:|---|---|
| FR-AUTH-006 | P0 | 自托管实例必须有首个账号创建机制；管理员可关闭后续开放注册。 | 全新数据库可创建首个账号，关闭注册后返回明确错误。 |
| FR-SYNC-001 | P0 | Agent 保存单调同步游标，断线后按游标补拉元数据和任务变化。 | 丢弃 WebSocket 消息后重连，最终状态仍一致。 |
| FR-SYNC-002 | P0 | 每个账号内的变更事件具有稳定序号；重复事件可安全应用。 | 同一事件应用两次不改变最终状态。 |
| FR-IDEM-001 | P0 | 创建/修改/删除/任务操作携带 `Idempotency-Key`；服务端保存结果摘要。 | 重放相同请求返回同结果，键冲突返回 `409`。 |
| FR-PATH-001 | P0 | 逻辑路径统一使用 `/`、Unicode NFC、区分大小写；拒绝空段、`.`、`..`、绝对本地路径和平台保留名。 | 跨三平台运行同一组路径契约测试。 |
| FR-IPC-001 | P0 | CLI/GUI 复用 Agent 应用服务，不直接操作 SQLite 或对象目录。 | CLI 和 GUI 的同一操作产生相同领域事件。 |
| FR-GC-001 | P0 | 已注销设备不再阻塞永久 GC；活跃设备删除确认或 tombstone 到期后才可回收。 | 离线、注销、重新上线三类场景均无数据复活。 |
| FR-SEC-001 | P0 | Refresh Token 只存哈希，轮换且能检测已使用 Token 的重放。 | 重放旧 Refresh Token 会撤销对应会话族。 |
| FR-SEC-002 | P0 | Agent 本地凭据存入系统安全存储；不可用时采用权限受限文件并明确降级。 | 各平台安全存储适配器有集成测试。 |
| FR-OPS-001 | P0 | 控制服务提供存活、就绪和指标端点；就绪检查包含数据库和迁移版本。 | 依赖不可用时 readiness 失败但 liveness 保持。 |
| FR-OPS-002 | P0 | `control-server`、`control-worker`、数据库迁移任务及后续 `relay-bootstrap` 必须构建为可追溯 OCI 镜像，并由 Docker Compose 完成 V1 单机部署。 | 全新 Linux 主机只安装 Docker/Compose、注入外部配置与机密后即可启动；镜像标签可追溯到版本和提交。 |
| FR-OPS-003 | P0 | 服务端容器遵循单进程、非 root、最小权限、只读根文件系统、标准输出日志、健康探针和 `SIGTERM` 优雅退出契约。 | 容器安全检查通过；停止时不接收新请求并在宽限期内退出；删除并重建应用容器不丢权威状态。 |
| FR-OPS-004 | P0 | 配置通过环境变量注入，机密通过 Docker secret/只读文件注入；数据库使用持久卷，应用容器不得挂载对象正文目录或 Docker socket。 | 镜像与仓库秘密扫描无凭据；轮换机密不需重建镜像；卷审计只发现 PostgreSQL 数据。 |
| FR-BACKUP-001 | P1 | 支持导出/恢复服务端元数据备份，并记录恢复演练结果。 | 空实例恢复后目录、设备、任务和策略一致。 |
| FR-LAN-001 | P0 | Android 必须通过 Control Server 登录并取得短期访问凭据；Agent 对缺失、过期或账号不匹配的凭据默认拒绝。 | 未认证访问文件列表、上传和下载均返回 `401/403`；登录后相同请求成功。 |
| FR-LAN-002 | P0 | Android 使用系统文件选择器读取上传源，不依赖真实文件路径或全盘存储权限。 | 从 Downloads 和第三方 DocumentsProvider 各选择一个文件并成功上传。 |
| FR-LAN-003 | P0 | 上传必须流式、有大小上限、可查询已提交偏移并在连接中断后恢复；未完成上传不得进入文件列表。 | 上传中途断网，恢复后只补传剩余数据；完成对象 SHA-256 与源文件一致。 |
| FR-LAN-004 | P0 | 下载支持标准字节范围和条件请求，Android 写入系统文件创建器返回的 URI；完成后核对服务端声明的 SHA-256。 | 中断后从非零偏移恢复，目标文件大小和 SHA-256 与 Ubuntu 对象一致。 |
| FR-LAN-005 | P0 | 文件列表至少返回稳定 ID、原始显示名、大小、SHA-256、MIME 和创建时间；同名文件不得静默覆盖。 | 上传两个同名不同内容文件得到明确冲突或两个明确区分的条目。 |
| FR-LAN-006 | P0 | Ubuntu Agent 只发布 SQLite 中为 `READY` 且磁盘反向校验存在的对象；临时文件、符号链接和损坏对象不可下载。 | 删除或篡改对象后列表/下载拒绝，重启恢复结果一致。 |
| FR-LAN-007 | P0 | Docker 控制面、Ubuntu Agent 和 Android APK 必须提供版本信息；部署和测试输出记录同一构建版本。 | E2E 记录镜像标签、Agent 版本和 APK versionName/versionCode。 |
| FR-LAN-008 | P0 | 交付门禁必须从真实 TCP socket 执行 bootstrap/login、上传、列表、Range 下载、完整下载、Hash 校验、未认证拒绝、重启后再下载和清理。 | `make lan-e2e` 在全新测试目录通过；任何一步失败均非零退出且保留诊断日志。 |
| FR-LAN-009 | P0 | 启用 LAN API 的 Ubuntu Agent 可通过标准 DNS-SD/mDNS 发布 `_sharedisk._tcp`；Android 可发现并选择候选 Agent，同时保留手工地址。发现结果不是信任凭据。 | 同网段发现后自动填入地址；伪造广播或无有效 Access Token 的请求仍被拒绝；mDNS 不可用时可手工连接。 |
| FR-LAN-010 | P0 | 用户可重命名自己的活动文件；名称执行与上传相同的 Unicode NFC 和长度校验，同账号活动文件不得重名。 | 重命名后 ID、对象 Hash 和正文不变；空名/非法名返回 `400`，冲突返回 `409`，其他账号不可修改。 |
| FR-LAN-011 | P0 | 删除活动文件只进入 7 天回收站，普通文件列表立即隐藏；回收站可列出删除时间和到期时间并恢复。 | 删除、重启 Agent、恢复后状态和内容一致；恢复遇到同名活动文件返回 `409`，不覆盖现有文件。 |
| FR-LAN-012 | P0 | 用户可立即永久删除回收站条目；若对象仍被其他逻辑文件引用，不删除正文；最后一个引用删除后安全回收本地对象。 | 两个条目共享同一 Hash 时永久删除一个仍可下载另一个；删除最后一个后列表、下载和对象文件均不可用；中断后重试可收敛。 |

## 7. 明确的 V1 语义

- 导入默认采用“复制到受管对象区”；不移动或删除用户原文件。
- 同目录同名冲突默认返回 `409 NAME_CONFLICT`，由客户端显式选择自动改名；不隐式覆盖。
- 账号内逻辑路径区分大小写，显示名保留原样；客户端下载到不区分大小写的平台时先做冲突检查。
- 来源设备只用于审计和展示，不决定后续下载源，也不因来源设备注销而改变。
- 自动推送本质是目标设备执行的持久副本任务；Android 是否立刻执行受系统后台限制约束。
- `desired_replicas` 统计 `READY` 副本，默认包含首次导入设备。
- 删除 tombstone 默认保留 30 天；仍未确认的活跃设备继续阻止对象物理 GC。设备注销后不再阻止。
- 控制服务不可用时，本地 `READY` 文件可打开；导入可先进入本地待同步队列，但在服务端确认前不对其他设备可见。
- LAN 发现只减少地址录入，不改变认证和 TLS 边界；客户端必须允许用户核对并覆盖发现地址。
- LAN 文件恢复保留原名称；若该名称已被活动文件占用，恢复失败并保留回收站记录。

## 9. 非阻塞开放项

以下事项不阻塞 LAN V1 核心实现，但必须在对应后续阶段入口前关闭：

- Android LAN V1 采用可侧载 APK；应用商店签名和升级策略推迟到发布阶段。
- 首个账号是开放注册、一次性注册码还是运维命令创建；默认采用“一次性初始化令牌”。
- NAS 是否仅运行 Linux Agent/CLI；默认是，不单独开发 NAS UI。
- 服务器域名、证书和邮件能力；密码重置在无邮件服务时由管理员执行。
- 受信 LAN 的 TLS 证书由用户现有 CA/反向代理提供；自动签发和首次信任引导不属于 LAN V1。
- 是否要求本地对象静态加密；V1 默认依赖设备磁盘加密，不自建文件加密格式。
