# 个人分布式云盘系统设计文档索引

本目录以《个人分布式云盘系统_需求与总体设计_v0.1.docx》为需求来源。后续开发按以下顺序使用文档：

1. [需求基线与验收追踪](./01_需求基线与验收追踪.md)：明确范围、业务不变量、补充需求、默认假设和验收追踪。
2. [架构设计方案](./02_架构设计方案.md)：记录技术选型、组件边界、数据流、一致性、安全、部署和架构决策。
3. [代码规范](./03_代码规范.md)：约束 Go、SQL、API、并发、日志、安全、测试和代码评审。
4. [详细设计与实现方案](./04_详细设计与实现方案.md)：定义数据模型、接口契约、状态机、事务、传输协议和关键算法。
5. [开发阶段性目标](./05_开发阶段性目标.md)：唯一推荐的开发顺序，以及每一阶段的输入、交付物、验证命令和退出条件。
6. [局域网部署与验收](./06_局域网部署与验收.md)：给出 Docker 控制面、Ubuntu Agent、Android APK 的可重复启动和文件互通验收路径。
7. [客户端功能与 UI/UE 基线](./07_客户端功能与UIUE基线.md)：说明 Android、Ubuntu 与可选管理台的当前用户可见范围。

## 文档优先级

发生冲突时，优先级从高到低为：

1. 已确认的需求基线与业务不变量；
2. 已批准的架构决策（ADR）；
3. OpenAPI、Protocol Buffers、数据库迁移等可执行契约；
4. 详细设计；
5. 示例、线框和阶段建议。

需求变化必须先修改需求及验收追踪，再评估架构和实现影响。不得只改代码而让文档中的状态机、API 或数据约束失真。

服务器端交付另有一条强制约束：`control-server`、`control-worker`、数据库迁移任务以及后续 `relay-bootstrap` 必须以 OCI 镜像交付，并以 Docker Compose 作为 V1 单机部署和验收基线。开发过程、临时测试输出和验收记录不作为产品文档纳入版本库；可执行契约以 OpenAPI、Proto 与迁移文件为准。
